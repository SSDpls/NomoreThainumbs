# ข้อจำกัดที่ทราบ (Known Limitations)

## แอปที่รันแบบ elevated (Administrator)

ความปลอดภัยด้านอินพุตของ Windows ป้องกันไม่ให้โปรเซสที่รันในระดับ medium
integrity (แอปปกติที่ไม่ได้ elevate — ซึ่ง No more Thai Nums ตั้งใจเป็นเช่นนั้น)
มองเห็นหรือฉีดอินพุตคีย์บอร์ดเข้าไปในโปรเซสที่รันแบบ **elevated**
(Administrator) อย่างเป็นรูปธรรม:

- Low-level keyboard hook ยัง*ทำงาน*อยู่ทั้งระบบ แต่ OS จะบล็อกไม่ให้ผลลัพธ์
  ของ hook ไปกระทบการประมวลผลอินพุตของหน้าต่าง elevated และ `SendInput`
  ที่ฉีดเข้าไปจะถูกเป้าหมายแบบ elevated เมิน
- ผลคือ: ข้อความที่พิมพ์ลง elevated Command Prompt, elevated PowerShell,
  กล่อง "Run new task" ของ Task Manager แบบ elevated, หน้าต่าง UAC และหน้าต่าง
  ลักษณะเดียวกัน จะยังได้เลขไทยตามเดิม

นี่คือการตัดสินใจเชิงออกแบบ ไม่ใช่การลืม:

- การรัน No more Thai Nums แบบ Administrator ถาวร ทำให้ยูทิลิตี้เล็ก ๆ ตัวหนึ่ง
  ถือสิทธิ์สูงโดยไม่จำเป็น บั่นทอนการแยกระดับสิทธิ์ที่ Windows ออกแบบไว้
  และทำให้ผู้ใช้ไม่อยากใช้ — เป็นการแลกที่ไม่คุ้มกับฟีเจอร์สมาธิปัตย์
- ทางแก้เชิงปฏิบัติสำหรับกรณี elevated terminal ที่พบไม่บ่อย คือพิมพ์เลข
  อารบิกจากเลย์เอาต์ภาษาอังกฤษ (Win+Space) หรือใช้เลขที่ไม่ต้องกด Shift
  ในจุดที่แอปเป้าหมายรองรับ

โค้ดแยกประเด็น elevation ไว้ใน keyboard engine เพียงจุดเดียว หากเวอร์ชัน
อนาคตต้องการเสนอ elevated helper แบบ opt-in ก็จะเพิ่มรอบ ๆ
`KeyboardHook`/`KeyInjector` โดยไม่ต้องแตะชั้น conversion หรือ UI

## ข้อจำกัดด้านแพลตฟอร์มอื่น

- **แอป Raw Input / DirectInput** (เกมจำนวนมาก, remote desktop หรือ
  virtualization host บางตัว) อ่านอินพุตจากฮาร์ดแวร์ตรง ๆ โดยไม่ผ่านท่อ
  ประมวลผลอักขระปกติ การแปลงจึงไม่ทำงานที่นั่น
- **Secure desktop** (หน้าล็อกอินของ Windows, หน้าต่างยืนยัน UAC) ได้รับ
  ข้อยกเว้นโดยการออกแบบ — แอป user-mode ทั่วไป hook ได้ไม่ถ้าไม่มีสิทธิ์พิเศษ
- **IME** (ภาษาญี่ปุ่น จีน เกาหลี) ส่งอินพุตผ่านท่อ composition ของตัวเอง
  ยูทิลิตี้นี้ตั้งใจไม่เข้าไปยุ่ง อย่างไรก็ตามเลย์เอาต์ไทยไม่ได้ใช้ IME
  จุดนี้จึงไม่กระทบกรณีการใช้งานเป้าหมาย
- **แอปที่รีแมปคีย์บอร์ดเอง** (เครื่องมือ macro, ปลั๊กอิน IDE บางตัว) อาจ
  ทำงานร่วมกับ global hook ได้หลากหลาย แต่ยูทิลิตี้นี้แทนที่เฉพาะคีย์สโตรก
  ที่ตัวอักษรที่ได้*เป็นเลขไทยพอดี*เท่านั้น ขอบเขตผลกระทบจึงถูกจำกัดไว้
  ตั้งแต่การออกแบบ

## หมายเหตุเชิงพฤติกรรม

- การวาง (Ctrl+V) ข้อความเลขไทยจะ*ไม่*ถูกเขียนใหม่ — แปลงเฉพาะการพิมพ์จริง
  เพราะแอปตัวนี้แก้*การพิมพ์* ไม่ใช่ข้อความที่เก็บไว้แล้ว
- จะติดตั้ง keyboard hook หนึ่งตัวต่อ session ของผู้ใช้ที่ล็อกอินอยู่
  ไม่กระทบ session ของผู้ใช้อื่น
